# Тестовое задание компании CyberYozh

Сделал несколько этапов эволюции проекта. Сразу обозначу, что сделано это было только потому что было время и интерес, как третий этап можно реализовать при использовании Django.

### MVP
Первый этап, в случае, когда задача нужна "вчера", вся работа максимально переложена на Django.
Скорость реализации с таким подходом высокая, подходит для проверки гипотез, очень горящих задач и самых простейших CRUD-сервисов, но при этом не заложена никакая архитектура проекта, что в будущем, если это всё не отрефакторить вызовет боль при добавлении новых фич. Бизнес-логика перемешана с инфраструктурой, юнит-тесты писать очень сложно из-за необходимости большого количества моков, изменения вносить так же довольно сложно т.к. всё между собой взаимосвязано.

### Services
Следующий этап с выделением сервисов и выносом бизнес-логики в них. Здесь я намеренно не стал выделять полноценные сущности под бизнесовые объекты, из-за этого всё ещё код очень сильно зависит от инфраструктуры, но теперь появляются мысли в сторону архитектуры проекта.
Скорость реализации уже пониже (в случае, если речь идёт о полноценной слоистой архитектуре с разделением на репозитории, полным отделением бизнес-логики от инфры и т.д.), подходит для систем с наличием хоть какой-то бизнес-логики, полное разделение в разы упростит написание тестов, расширение функционала, внесение изменений.

## Запуск проекта
Для запуска проекта используется docker compose
```sh
docker compose up -d
```
Либо можно запустить проект через `make`
```sh
make run
```

## Запуск тестов
Т.к. для тестов требуется БД, их необходимо запускать через docker compose
```sh
docker compose run web python manage.py test
```
Либо можно запустить через `make`
```sh
make integration-tests
```
